一
为俯视角2D游戏项目设计并实现一个完整的玩家角色场景，具体要求如下：

1. 玩家角色基础实现：
   - 创建玩家角色节点结构，包含碰撞体、动画播放器和状态机组件
   - 实现角色基本属性（位置、朝向、速度等）的管理系统
   - 不包括设计角色视觉表现，包括角色精灵和基础动画帧

2. 状态机系统实现：
   - 依靠limbo插件中的节点构建玩家状态机，至少包含idle（ 空闲）和move（移动）两种基础状态
   - 实现状态间的稳定过渡，包括完善的触发条件和合理的过度效果
   - 为动画系统设计参数接口，支持后续添加更多动画状态

3. 状态机扩展性设计：
   - 预留状态机扩展的可能性，支持未来添加复杂状态
   - 实现状态机事件声明和回调机制，允许外部系统响应状态变化
   - 设计状态优先级系统，处理多状态同时触发的冲突问题

4. godot_core_system代码库资源整合：
   - 分析godot_core_system代码库，识别可复用的模块和工具类
   - 标注可用于本项目的具体组件（如：角色控制器、动画管理工具、状态机框架等）
   - 制定代码库资源的集成方案，确保兼容性和可维护性

5. 开发大纲：
   - 第一阶段：需求分析与技术选型，godot_core_system代码库资源整合
   - 第二阶段：玩家角色节点结构设计与实现
   - 第三阶段：基于limbo插件的状态机基础实现
   - 第四阶段：动画系统整合与调试
   - 第五阶段：扩展性接口设计与实现
   - 第六阶段：测试与优化
   - 其中每一阶段都需要和我确认之后再继续进行，确保项目进度和质量

6. 交付物要求：
   - 完整的玩家角色场景文件（.tscn）
   - 状态机实现代码及相关脚本
   - 动画资源配置文件
   - godot_core_system代码库资源使用说明

7. 技术约束：
   - 遵循Godot引擎最佳实践和编码规范
   - 确保代码可维护性和可扩展性
   - 优化动画播放性能，确保在目标设备上流畅运行
   - 状态机逻辑需清晰可调试，包含必要的日志输出

二
重新摆清楚项目的定位。
我们要做的游戏是一款3d俯视角的像素风格类博德之门游戏，由数名玩家操纵数名角色（角色数量大于等于玩家数量）在自由探索状态是平面全向自由移动，
在战斗中是在世界中进行回合制类战棋游戏的样子，拥有可自由探索的嵌套式大世界（大地图>城市>房间类似的嵌套关系），未来要有联机功能，
有丰富的故事系统和任务系统，并有一定的随机性来像roguelike游戏一样有重复游玩价值。永远记住这条并活用于未来的项目编程
